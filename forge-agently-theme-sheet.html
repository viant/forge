Where the components overlap

These are the areas to clarify before pushing more visual changes toward production.

Amber = overlap
Area
Current split
Decision needed
Shell controls
Forge owns reusable control anatomy; Agently owns shell placement and shell-specific states.
One state contract. No duplicate button, focus, disabled, or status recipes.
Typography & spacing
Forge exposes roles; Agently applies them across conversation and workspace shell.
Agently should select roles; Forge should own generic type behavior.
Panels, lookup, tables, pagers
Forge is the intended shared owner; Steward/Agently still carry compatibility styling.
Move geometry into Forge and leave product choice in Steward metadata.
Chat and tool feeds
Agently owns conversation composition; Forge renders reusable result, table, and window components.
Define the handoff boundary so feed chrome is not recreated in Forge.
Responsive behavior
Both layers currently contain responsive rules in different places.
Component stacking belongs with the rendered owner; remove duplicate mobile overrides.
Theme publication
Steward AI publishes selected values; Forge and Agently consume the roles.
Treat the published style catalog as the production source of truth.
Bottom lineForge should own reusable component anatomy and behavior. Agently should own the application shell and conversation composition. Steward AI should choose product-specific variants and publish the theme values. The biggest collision zones are controls, typography/spacing, panels/tables/pagers, chat/feed handoff, and responsive rules.

This is a visual review sheet for the current local branches. It does not claim that these values are active in production.
